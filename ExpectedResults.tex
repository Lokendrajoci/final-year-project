\chapter{CURRENT PROGRESS, DATASET COLLECTION, AND FUTURE WORK}

\section{Dataset Collection}

A structured multimodal dataset has been collected to support the training and
evaluation of the proposed guardrail. The dataset consists of text, images,
and paired text-and-image samples curated to represent both malicious
(jailbreak) and benign interaction scenarios. This ensures that the model
learns to distinguish genuinely harmful multimodal inputs from safe ones
rather than relying on superficial patterns.

\subsection{Data Categories}

The collected dataset is organized into the following categories, aligned with
the three primary jailbreak failure modes identified in Chapter 2:

\begin{itemize}

    \item \textbf{Typographic Injection Samples:}
    Images in which harmful or policy-violating instructions are rendered
    directly as visual text (e.g., embedded within the image using overlays,
    stylized fonts, or scene-text placement). These samples are paired with
    minimal or neutral accompanying user text, isolating the image as the
    primary attack vector.

\subsection{Custom Dataset Curation}

In addition to leveraging existing labeled samples, a custom data collection
process was carried out to increase category coverage and reduce dependency
on a single data distribution. This involved:

\begin{itemize}

    \item Manually curating additional query-relevant pairing examples by
    combining benign images with contextually related text prompts to
    simulate realistic attack scenarios not well represented in existing
    samples.

    \item Generating supplementary typographic injection samples by rendering
    varied instruction text onto diverse image backgrounds, fonts, sizes,
    and orientations to improve OCR-branch robustness.

    \item Collecting additional benign multimodal pairs from general-purpose
    image-text sources to balance the ratio of safe to unsafe samples and
    reduce class imbalance during training.

    \item Applying a manual review and relabeling pass on a subset of the
    aggregated dataset to verify category correctness and remove ambiguous
    or mislabeled samples.

\end{itemize}

\section{Current Progress}

The project has progressed through data preparation and has moved into
system-facing development. Key achievements are summarized below:

\begin{itemize}

    \item \textbf{Dataset Collection and Curation:}
    A categorized multimodal dataset covering typographic injection,
    query-relevant pairing, and adversarial perturbation has been collected,
    supplemented with custom-curated data, and is undergoing preprocessing.

    \item \textbf{System Architecture Finalization:}
    The tri-branch encoder design, feature fusion module, and calibrated
    threshold-based decision mechanism have been finalized, as detailed
    in Chapter 3.

    \item \textbf{User Interface Development:}
    An interactive user interface is under active development to allow
    end users to submit multimodal requests and view the guardrail's
    classification decision in real time.

\end{itemize}


\subsection{User Interface Design and Placement}

The user interface serves as the front-facing interaction layer of the
system, allowing a user to upload an image, enter an accompanying text
prompt, and submit the combined request to the guardrail pipeline. Upon
submission, the interface displays the computed risk score along with the
final decision (Allow or Block).

If the request is allowed, it is forwarded to the protected
Vision-Language Model and the generated response is displayed to the user.
If the request is blocked, a rejection notice is shown instead.

\section{Challenges}

Several challenges have been encountered and are anticipated during the
remaining phases of the project:

\begin{itemize}

    \item \textbf{Data Imbalance:}
    Jailbreak samples, particularly adversarial perturbation examples, are
    comparatively harder to source and construct than benign samples,
    leading to class imbalance during model training. Careful resampling
    and augmentation strategies are being explored to mitigate this.

    \item \textbf{OCR Reliability:}
    Optical Character Recognition accuracy can degrade on stylized,
    distorted, low-contrast, or unusually oriented typographic injections,
    potentially reducing the effectiveness of the OCR text branch and
    requiring additional preprocessing steps.

    \item \textbf{Label Ambiguity:}
    Some collected samples, particularly in the query-relevant pairing
    category, require subjective judgment to label correctly, introducing
    potential inconsistency during manual review.

    \item \textbf{Generalization to Unseen Attacks:}
    Since jailbreak techniques evolve rapidly, ensuring the guardrail
    generalizes to attack variants not present in the training data remains
    a significant challenge.

    \item \textbf{Computational Constraints:}
    Balancing detection accuracy with the lightweight, low-latency design
    goal of the guardrail requires careful tuning of encoder sizes,
    projection dimensions, and fusion module complexity.

    \item \textbf{UI-Backend Integration:}
    Ensuring smooth, low-latency communication between the user interface
    and the backend guardrail pipeline, particularly for image uploads and
    real-time score display, requires further engineering effort.

\end{itemize}


\section{Future Work}

The following tasks are planned for the upcoming phases of the project:

\begin{itemize}

    \item Complete preprocessing, cleaning, and augmentation of the collected
    dataset to address class imbalance and improve robustness across all
    four categories.

    \item Implement and train the vision encoder, OCR text encoder, and user
    text encoder branches, followed by integration of the feature fusion
    module and classification head.

    \item Finalize the user interface and complete its integration with the
    backend guardrail pipeline for end-to-end testing.

    \item Conduct threshold calibration experiments to optimize the
    Allow/Block decision boundary and minimize false-positive rates.

    \item Perform ablation studies to evaluate the individual contribution
    of each branch (raw image, OCR text, user text) to overall detection
    performance.

    \item Evaluate the complete system using accuracy, precision, recall,
    F1-score, and false-positive rate, and compare results against existing
    baseline guardrail approaches discussed in Chapter 2.

    \item Conduct user testing on the interface to gather feedback on
    usability and refine the results display accordingly.

\end{itemize}
